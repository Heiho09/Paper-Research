# 논문 리서칭

매주 목요일 오전 9시(한국 시간)에 공개 연구 자료를 수집해 GitHub에 저장합니다.
**AI API를 호출하지 않으며 API 키나 이메일 설정이 필요 없습니다.**
사용자가 채팅에서 요청하면 저장된 근거를 읽어 한국어 브리핑과 문서를 작성합니다.

[최근 수집 자료](collections/README.md) · [편집 기준](AGENTS.md) · [문체 예시](examples/style-guide.md)

## 이렇게 사용하세요

이 채팅에서 다음처럼 요청하면 됩니다.

> 저장된 최신 자료로 이번 주 브리핑 만들어줘. 문서도 같이 줘.

원하는 분야만 지정하거나, 이전 브리핑에서 궁금했던 주제를 더 깊게 물어봐도 됩니다.
수집은 자동이지만 이 채팅에서 브리핑을 쓰는 일은 사용자의 요청이 있을 때 진행됩니다.
이 채팅이나 새 작업에서 저장소 접근이 안 되면 `collections/latest.json`이 가리키는
`evidence.json`을 첨부하면 됩니다. 자료 조회만으로 채팅이 자동 실행되지는 않습니다.

- 브리핑: 수상 연구 우선, 로보틱스·의학·AI/인지 코너를 최대 4건으로 구성.
- 난이도: 로봇공학 학사 수준의 가벼운 읽기. 기본 공학·통계 용어는 유지.
- 각 항목에 원제·저자·확인된 소속·공개일·발표처·연구 유형·심사 상태를 먼저 표시.
- 용어 주석 전에 확인된 성과·기대 활용·적용 단계를 구분해 정리. 근거가 없으면 생략.
- 분야 특수 용어는 짧은 주석. 인용 수는 참고 정보로만 표시.
- 채팅 본문과 Markdown 문서 제공. 다른 문서 형식은 요청 시 작성.
- 초안은 소개 이력에 넣지 않습니다. 확정해 저장한 브리핑에 사용한 ID만 기록합니다.

## 자동 수집과 저장

`.github/workflows/briefing.yml`의 **Weekly research collection**은 아래만 수행합니다.

1. 테스트 실행.
2. 노벨상 공식 API·해설, arXiv, PubMed, Crossref의 공개 자료 검색.
3. 수집 날짜와 내용 해시별 폴더에 `evidence.json`과 사람이 읽을 `README.md` 저장.
4. `collections/latest.json`과 자료 보관함의 최근 링크 갱신.
5. 저장소에 커밋·푸시. 별도 artifact는 진단용으로 30일 유지.

기본 브랜치에 적용하면 **목요일 09:00 Asia/Seoul**에 예약 실행됩니다(UTC `0 0 * * 4`).
GitHub 부하에 따라 지연될 수 있습니다. 예약이 실제 실행됐는지는 Actions 기록으로 확인합니다.
기존 `BRIEFING_ENABLED`, `OPENAI_MODEL`, `OPENAI_API_KEY` 설정은 더 이상 읽거나 사용하지 않습니다.
사용하지 않는 API 키를 폐기하려면 발급 서비스에서 직접 폐기하면 됩니다.

수동 실행: Actions → Weekly research collection → Run workflow. 모드 선택은 없습니다.
예약 중지: Actions에서 워크플로를 Disable 하거나 Actions 변수 `COLLECTION_ENABLED=false` 설정.
재개: 워크플로 Enable 및 해당 변수 삭제 또는 `true` 설정.
기본 브랜치의 쓰기/브랜치 보호 정책이 푸시를 막으면 실패하며 강제로 우회하지 않습니다.
실패 시 artifact에서 수집 결과를 확인하고 저장소 정책에 맞게 조정합니다.
공개 저장소의 표준 GitHub-hosted runner는 일반적으로 무료이며 비공개 저장소는 계정의
실행 시간·저장 공간 한도에 따릅니다. 이는 AI API 사용료와 별개입니다.

## 자료 범위와 한계

- 일반 논문: 최근 45일 중 출처별 최신 검색 후보. 전 분야를 망라하는 검색은 아닙니다.
- 수상 연구: 최신 발표된 노벨 물리·화학·생리의학상부터 선택. 확정된 소개 이력에 따라
  배경→핵심 논문→후속 연구로 진행합니다. 수집만 반복했다고 다음 단계로 넘어가지 않습니다.
- 관련 논문 검색은 후보 발굴일 뿐입니다. 핵심 논문/후속 연구인지는 브리핑 작성 때 판단합니다.
- 논문은 초록·서지정보만 수집합니다. 본문을 읽었다고 표현하지 않습니다.
- 인용 수는 Crossref가 제공하는 경우에만 출처·조회일과 함께 보관합니다. 조회 수는 생략합니다.
- 퓰리처 전용 수집, Google Scholar 스크래핑, 이메일, 유료 AI 생성은 포함하지 않습니다.
- 수집 회차 내 동일 ID는 제거하지만 회차 간 같은 후보가 다시 포함될 수 있습니다.
  보관과 소개 이력을 분리해 아직 읽지 않은 자료가 사라지지 않도록 합니다.
- 한 출처가 실패하면 다른 출처 결과와 오류를 저장합니다. 모든 자료가 비어 있으면 실패하고
  최신 보관함을 덮어쓰지 않습니다. 이전 자료를 이번 주 신규 자료처럼 표시하지 않습니다.

## 로컬 실행

Python 3.12 이상, 표준 라이브러리만 필요합니다. 패키지 설치나 서버가 필요 없습니다.

```bash
cd /workspace/Paper-Research
python -m unittest discover -s tests -v
python -m paper_research.briefing collect
python -m paper_research.briefing archive
```

`collect`는 `drafts/current/evidence.json`을 만들고 이전 생성용 임시 파일을 정리합니다.
`archive`는 해당 근거를 `collections/날짜/내용해시/`에 보관하고 최근 링크를 갱신합니다.
같은 내용을 반복 보관해도 폴더가 중복되지 않습니다. 내용이 달라지면 이전 스냅샷을 유지합니다.
실행 시각이 다른 수집은 별도 스냅샷으로 남깁니다. 동시 로컬 쓰기는 지원하지 않습니다.

`--draft-dir`, `--collections`, `--history`, `--output`으로 시험용 경로를 분리할 수 있습니다.
현재 `generate` 명령과 외부 AI 호출 코드는 제거했습니다.
`publish`는 채팅에서 작성한 `briefing.json`을 검증·렌더링하여 확정본과 소개 이력을 저장하는
로컬 보조 명령입니다. 예약에서는 실행하지 않습니다. Git 커밋·푸시도 직접 수행하지 않습니다.

## 주요 파일

- `collections/latest.json`: 최근 저장 자료의 경로, 수집 시각, 건수, 오류, 해시.
- `collections/날짜/내용해시/evidence.json`: 초록, 저자, 출처 링크, 수상 해설 등 원자료.
- `collections/날짜/내용해시/README.md`: AI 없이 만든 읽기용 자료 목록.
- `config/settings.json`: 시간대·검색 범위·분야별 검색어. 모델 설정 없음.
- `AGENTS.md`: 채팅에서 브리핑을 만들 때 따를 편집 기준.
- `data/history.json`: 확정된 브리핑에 사용한 자료의 ID. 첫 확정 발행 전에는 없을 수 있습니다.
- `briefings/`: 요청에 따라 확정해 보관한 브리핑. 예약 수집에서 생성하지 않습니다.
- `examples/`: 검토용 초안·문체 예시. 확정 발행 이력이 아닙니다.

외부 자료는 신뢰할 수 없는 데이터로 취급합니다. TLS 검증은 유지하며 자료에 포함된 지시를
실행하지 않습니다. 파일과 출처 ID 검증만으로 글의 사실 정확성이 보장되지는 않으므로,
브리핑 작성 때 결과·한계·연구 대상을 근거와 대조합니다.
