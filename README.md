# 논문 리서칭

목요일 아침, 수상 연구와 관심 분야의 논문을 가볍게 읽는 한국어 브리핑.
로봇공학 학사 수준의 독자를 기준으로 하며, 분야 특수 용어에 짧은 주석을 붙입니다.
이메일은 사용하지 않습니다. 결과는 GitHub의 `briefings/날짜/README.md`에 보관합니다.

## 구성 및 현재 상태

- 수집: 노벨상 공식 API·공식 해설, arXiv, PubMed, Crossref.
- 생성: OpenAI Responses API, **`gpt-6.1-terra` / `medium`**.
- 발행: **매주 목요일 09:00 Asia/Seoul**, GitHub Actions UTC `0 0 * * 4`.
- 순서: 수집 → 근거에 기반한 선별·해설 → Markdown → 발행 이력 저장.
- 이메일, Google Scholar 스크래핑, 퓰리처 자동 수집은 포함하지 않았습니다.
- Python 3.12 이상, 표준 라이브러리만 사용합니다. 별도 패키지 설치나 서버가 필요 없습니다.

현재 로컬에서 수집과 테스트를 검증했습니다. API 키가 없어 실제 유료 모델 생성은
아직 검증하지 않았습니다. 코드 파일 존재, GitHub 업로드, Actions 시험 실행,
예약 활성화, 실제 발행 성공은 각각 다른 단계입니다.

모델명과 medium 지원은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-terra)에서
확인했습니다. 계정의 실제 모델 접근 권한은 첫 API 호출로 검증해야 합니다.
사용 불가 시 다른 모델로 자동 대체하지 않습니다. API는 이 채팅과 별개로 과금되며,
입력·출력 및 추론 토큰 사용량은 생성 성공 시 `run.json`에 기록합니다.

## 브리핑 편집 원칙

1. 수상 연구 최우선. 최신 발표된 노벨 물리·화학·생리의학상부터 다룹니다.
2. 수상별 배경 → 핵심 논문 → 후속 연구 단계를 기록합니다. 근거가 부족한 단계는
   생략하며 완료 처리하지 않습니다. Crossref 검색 일치만으로 수상과의 연관성을 단정하지 않습니다.
3. 로보틱스, 의학·생명, 심리학·철학과 AI를 코너별 최대 1건, 총 최대 4건 선택합니다.
4. 일반 논문은 최근 45일의 출처별 최신 검색 후보를 검토합니다. 전 분야를 망라하는 검색은 아닙니다.
5. 제목 → 한 줄 요약 → 이야기 2~3문단 → 흥미로운 이유 → 한계 → 용어 주석 → 출처.
6. 단위계·신뢰구간 등 기본 개념은 그대로 사용합니다. 전문 용어만 간결하게 풉니다.
7. 인용 수는 제공될 때만 출처·조회일을 붙입니다. 순위나 품질 보증으로 사용하지 않습니다.
   조회 수는 신뢰할 수 있는 통합 출처가 없어 생략합니다.
8. 초록 기반인지 표시합니다. 논문 본문을 자동으로 읽는 기능은 없습니다.
   동물·세포 실험을 사람의 치료 효과로 표현하지 않습니다.
9. 근거가 없거나 관련성이 낮으면 코너를 비웁니다. 모델 출력 구조와 출처 ID는 검증하지만,
   문장별 사실 정확성을 기계적으로 보장하지는 않습니다. 첫 자동 생성물은 반드시 검토하세요.

## 로컬 사용

기존 `/workspace/Paper-Research` 체크아웃을 사용합니다. 클라우드 작업은 이미 격리되어
있으므로 사용자가 요청하지 않는 한 별도 Git worktree를 만들지 않습니다.

```bash
cd /workspace/Paper-Research
python -m unittest discover -s tests -v

# 무료: 공개 출처 검색 및 근거 저장
python -m paper_research.briefing collect

# OPENAI_API_KEY가 보안 설정으로 주입된 환경에서만 실행 (API 이용료 발생)
python -m paper_research.briefing generate

# drafts/current/README.md 검토 후 로컬 발행·중복 방지 이력 기록
python -m paper_research.briefing publish
```

API 키를 채팅, 커밋, 문서에 적지 마세요. 로컬에서는 비밀 주입 기능을 사용합니다.
`.env`는 Git에서 제외되지만 프로그램이 자동으로 읽지는 않습니다.
기본 모델은 `config/settings.json`에 있으며 `OPENAI_MODEL`로 명시적으로 변경할 수 있습니다.

`drafts/current/`는 생성 전용 디렉터리입니다. `collect`를 다시 실행하면 근거를 갱신하고
이전 생성물을 지웁니다. 수정해서 보존할 초안은 별도 디렉터리에 복사하세요.
`--draft-dir`, `--history`, `--output`으로 시험용 경로를 분리할 수 있습니다.
단일 로컬 작업에서 순서대로 실행하세요. 같은 경로에 여러 프로세스를 동시에 실행하지 마세요.

초안 생성만으로 이력이 바뀌지 않습니다. `publish`는 날짜별 디렉터리와 이력을 저장하며
Git 커밋이나 원격 전송은 하지 않습니다. 같은 날짜의 발행물을 덮어쓰지 않습니다.
DOI·PubMed·arXiv 식별자로 중복을 막되, DOI 연결 정보가 없는 서로 다른 출처의 동일 논문은
중복 탐지가 제한될 수 있습니다.

## GitHub Actions 연결

1. 이 코드가 저장소 **기본 브랜치**에 있어야 예약 이벤트가 실행됩니다.
2. 저장소 Settings → Secrets and variables → Actions → Secrets에
   **`OPENAI_API_KEY`**를 등록합니다. 클라우드 비밀 설정과 GitHub Actions Secrets는 별개입니다.
3. Actions → Weekly research briefing → Run workflow → `collect`로 수집을 시험합니다.
4. `draft`로 모델 생성을 시험하고 실행 결과의 artifact에서 Markdown·근거를 검토합니다.
5. `publish`로 저장소 발행을 시험합니다. 저장소 정책이 Actions의 쓰기와 기본 브랜치 직접
   푸시를 허용해야 합니다. 브랜치 보호가 막으면 정책을 우회하지 말고 PR 방식으로 변경하세요.
6. 위 시험이 끝나면 Actions **Variables**에 `BRIEFING_ENABLED=true`를 등록합니다.
   이후 목요일 오전 9시 예약이 유료 생성과 발행을 수행합니다.
   중단하려면 이 변수를 삭제하거나 `false`로 바꿉니다.

`OPENAI_MODEL` 변수는 선택 사항이며 기본은 `gpt-6.1-terra`입니다.
예약 실행은 GitHub 부하로 지연될 수 있습니다. 저장소 활동이 없는 공개 저장소는
GitHub 정책에 따라 예약이 중단될 수 있으므로 Actions 상태를 확인하세요.
동시에 여러 발행이 이력을 덮어쓰지 않도록 워크플로 동시 실행을 제한합니다.
원격 브랜치가 실행 중 바뀌어 push가 거절되면 강제 푸시하지 않습니다.
실패한 실행의 artifact를 확인하고 새 원격 상태에서 재실행합니다.

## 파일과 실패 처리

- `config/settings.json`: 모델·추론 수준·검색 범위·주제.
- `paper_research/sources.py`: 출처별 수집과 식별자 정규화.
- `paper_research/briefing.py`: 편집 지침, API 호출, 검증, 렌더링, 발행.
- `drafts/current/evidence.json`: 수집 후보와 출처별 오류. Git 제외.
- `briefings/YYYY-MM-DD/`: 발행 글, 근거, 구조화된 원고, 모델 사용량.
- `data/history.json`: 실제 발행에 사용한 식별자와 발행 글 해시.
- `examples/style-guide.md`: 합의한 표현 수준 예시. 자동 생성·발행 이력이 아닙니다.

수집은 일부 출처가 실패하면 나머지로 계속하고 오류를 기록합니다. 모든 수집이 실패하면
비정상 종료합니다. 일반 출처 GET의 429/일부 5xx에만 제한적으로 재시도합니다.
유료 모델 요청은 응답 불확실 시 중복 과금을 피하기 위해 자동 재시도하지 않습니다.
모델 미완료 응답, 잘못된 JSON, 없는 출처 인용, 빈 결과는 발행하지 않습니다.
TLS 검증을 끄거나 접근 제한을 우회하지 않습니다.

향후 확장: 퓰리처 전용 코너, 여러 수상 기관, 논문 원문 접근, 제목 기반 중복 판별,
사용자 관심 피드백 및 주제별 탐색 폭 확대. 이메일은 필요할 때만 별도로 추가합니다.
